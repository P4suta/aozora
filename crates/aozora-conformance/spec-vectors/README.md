# Vendored conformance vectors

This directory is a **vendored copy** of the conformance corpus from the
sibling specification repository
[`aozora-notation-spec`](https://github.com/P4suta/aozora-notation-spec):

```
spec-vectors/
├── vectors/<name>/vector.json   # one self-contained case per dir
├── schema/vector.schema.json    # JSON Schema the vectors validate against
└── RUNNER.md                    # the must/should/may comparison contract
```

## The specification is the source of truth — do not hand-edit

The spec is the master for 青空文庫記法 behaviour; this parser is one
processor under test against it. These files are **generated by
`just sync-spec-vectors`** (`scripts/sync-spec-vectors.sh`), which copies
them out of `../aozora-notation-spec/conformance/`. To change a vector,
edit it **in the spec repo**, then re-run the sync and commit the diff.

Two layers keep the loop honest:

- **In-tree gate (Docker / cloud CI):** `xtask conformance vectors`
  (run by `just conformance`) parses each vector's `source` and compares
  the parser's projections — `serialize`, `nodes`, `pairs`,
  `diagnostics` — against `expected`, governed by `meta.level`
  (`must` fails the build, `should` warns, `may` is informational). The
  `html` channel is **informative** (spec §8) and only ever warns.
- **Host drift check (pre-push):** `just verify-spec-vectors`
  (`scripts/verify-spec-vectors.sh`) fails the push if this vendored copy
  has drifted from the sibling spec repo. It is a no-op where the spec
  isn't checked out, so the vendored copy is authoritative in CI.

We vendor (rather than a submodule / crates.io pin) so the gate needs no
network and no checked-out sibling — see ADR notes in the spec repo.
